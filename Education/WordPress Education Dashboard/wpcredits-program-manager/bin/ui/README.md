# The UI rig (local Docker copy only)

1. `bin/ui/copy.sh prepare <plugin.zip>`: snapshots the copy at http://localhost:8900, collects the names to refuse into the work folder, installs the zip, scrubs people and puts `wpcpm-ui-rig.php` in mu-plugins.
2. `node bin/ui/snap.mjs --out <folder>`: makes the invented items (`seed.mjs`; `--skip-seed` reuses them) and photographs every scene of `scenes.mjs` at 1280 and 390 (`--sizes 1280,390,768` adds release 2's tabs at 768); `--only` takes parts of file names. The seed stores a frozen moment (`wpcpm_ui_rig_now`, in ui-ready): the pages' scripts and every relative time the plugin prints through `human_time_diff()` read it, so two runs from one ui-ready are pixel-equal; counts of whole days the plugin works out from `time()` still move with the date.
2b. `--no-pictures` takes the numbers and no picture: each scene is staged, its `expect` read, the overflow facts and Gate B's measures (`collect.mjs`, `gateMeasures()`) written to `measures.txt`, and a picture is saved only where a line fires (an overflow line, a measure `OFF`, a gap off the rhythm, a failed `expect`, a broken picture), each listed in `fired.txt`. The names to refuse still hold.
2c. Two seeded schools have a site icon, each a file of the copy's own uploads, so nothing is asked for off this machine (`seed.mjs`, `ICONS`; `seed-states.php`, `icons`): the design school's is a picture the seed writes, which loads; the long-word school's names a file that is not there, so the copy answers 404 and the icon takes itself off the page. Their Overview scenes expect the head so (`scenes.mjs`: `SITE_ICON` on `overview-contact`, `SITE_ICON_GONE` on `long-words-overview`), and a round draws the head beside an icon and the head whose icon did not load (1.123.97).
3. `node bin/ui/measure.mjs --out <file.json>`: the computed-style counts of design section 8 item 4, one line per screen.
4. `node bin/ui/compare.mjs <before folder> <after folder>`: `same`, `DIFFERS` or `MISSING` per file, then `N differ`; exit 1 on any.
5. `bin/ui/copy.sh swap <other.zip>` compares two builds in one prepared session: it puts the database back to `ui-ready` (the same invented items and frozen moment) and installs the other zip beside `.worktrees`; then `snap.mjs --skip-seed` and `compare.mjs`. A baseline is only comparable with pictures from the same seeded state.
6. `bin/ui/copy.sh restore` puts the copy back, after any number of swaps. Outputs go outside the repository or under `.superpowers/`; tools are found through `WPCPM_DOCKER`, `WPCPM_PLAYWRIGHT`, `WPCPM_UI_WORK`, `WPCPM_FFMPEG` and `WPCPM_FFPROBE`, with home-folder defaults.

7. The layout harness, `bin/ui/layout/`, needs no site: `dump.php` keeps the markup a suite draws (`WPCPM_LAYOUT_OUT=<cases.json> php -d auto_prepend_file=bin/ui/layout/dump.php bin/test-x.php`, the suite calling `wpcpm_layout_keep( $name, $html )` guarded by `function_exists`).
8. `node bin/ui/layout/run.mjs --in <cases.json> [--out <result.json>] [--widths 358,569,...] [--only <substring>] [--off] [--census <census.json>]` draws every case in the dashboards' frame and sheets at eight main-area widths (358 to 960) in headless Chrome, each in the window a reader has (under 800: one window; from 800 up twice, menu `folded` and `open`), then again with every hidden `wpcpm-ui-panel` opened (`panels open`), and prints `ok` or `FAULT` (overflow, a cell wider than its box, sideways scroll) per case and width, then `<N> faults`; exit 1 on any. `--census` writes every gap between neighbouring blocks and every left edge (measure.js, `wpcpmCensus`), each with both blocks' kinds and words; from it the run fails `GAP` (under 6px between words and a control or a button, or off the rhythm; on the Institution Dashboard only) and `EDGE` (a legend off its fields' edge, on every surface). `bin/test-ui-layout.php` draws every suite's cases in one run and holds the findings still to fix in one list, `$known`: it fails on a finding not on the list and on a listed one that no longer fires, so a fix takes its lines off in the same commit (the list is empty since Gate B's third round). It also draws the Institution Dashboard's head beside a school's site icon three ways at main 960 and 358 (the icon drawn, the icon refused and gone, no icon), answering the icon's address itself: in the ordinary run a kept head's icon is lazy and far below the window, so it is never asked for and never gone.
9. It finds Playwright through `WPCPM_PLAYWRIGHT` and the theme through `WPCPM_THEME_DIR`, with home-folder defaults; `--off` draws the cases without `wpcpm-ui-on`, for an old branch.
10. The harness measures the frame's main area only: the side menu (`.wpcpm-frame__menu`) is left out of every pass and the run says so; `--ignore <css selector>` (repeatable) also leaves out the elements matching it, and its selector is printed in the run's header.
11. Every case is drawn on its surface, the dashboard page it belongs to (`page.mjs`, `SURFACES`): `institution`, `administrator` (or `administrator/<view>`, `overview` by default) and `sponsor` (or `sponsor/<view>`). A suite names it in `wpcpm_layout_keep( $name, $html, $surface )`; without one, `dump.php` takes the suite's own from its list of suites whose every drawing is one dashboard's (the Institution Dashboard's: `test-institution*-`, `test-semester-report.php`, `test-sponsor-event-list.php`, `test-parts-file.php`), and `run.mjs` refuses a case that still names none. The Student and Mentor Report Cards are not in the frame and are not drawn. Each surface's page is drawn as the site prints it: the body classes (`page-template-page-<page>-dashboard`, `wpc-dashboard-page`, `wpc-<page>-page`, `wpc-signed-in` and WordPress's own), the template's wrappers (`.wp-site-blocks`, the main group `.wpc-main.wpc-main--app.wpc-main--<page>`, the post content `.wpc-app__content`), the frame as `WPCPM_Dashboard_Frame::open()` prints it (`.wpcpm-frame.wpcpm-frame--<page>`, with `wpcpm-ui-on` where the surface is live, `.wpcpm-frame__body`, `.wpcpm-frame__main`, the container `wpcpm-main`; no top bar, no menu) and the page's root inside the main area as the dashboard's `render()` prints it (`.wpcpm-dashboard.wpcpm-institution`, `.wpcpm-dashboard.wpcpm-administrator.wpcpm-administrator--<view>`, `.wpcpm-dashboard.wpcpm-sponsor.wpcpm-sponsor--<view>`; a case that starts with its root is that root). The sheets are in that page's order: what its `render()` enqueues (the Institution Dashboard: parts, dashboard, institution, the frame's, report-print; the Administrator Dashboard: parts, dashboard, administrator, cohort-timeline, the frame's; the Sponsor Dashboard: parts, dashboard, administrator, sponsor, the frame's), then WordPress's `block-library.css` (the main group's and the post content's block styles and the block library's `common.css`) and `global-styles.css` (the presets and custom values as variables on `:root`, the body, link, heading and button element styles, the layout rules, the custom CSS), then the theme's `style.css`, the dashboard sheets not printed yet, the theme's `dashboard.css` and `hub.css` (the Inter and EB Garamond faces). Only the main area's boxes are measured. Each run prints its surfaces, their sheets and where the global styles came from.
12. The two WordPress sheets are a fixture beside the harness, made by WordPress itself: `WPCPM_THEME_DIR=<theme folder> node bin/ui/layout/refresh-global-styles.mjs` hands that folder's `theme.json` to WordPress and Gutenberg on the Docker copy (`global-styles.php` piped to its `bin/wp eval-file -`, the copy's theme and every plugin but Gutenberg left out; it stops on any database query that is not a read) and writes `global-styles.css`, `block-library.css` and `global-styles.json` (the theme.json's sha256, the theme's version, WordPress's and Gutenberg's versions, the blocks and files read). The refresh runs one command on the copy, `bin/wp eval-file - --skip-themes --skip-plugins=<every plugin folder but gutenberg>`; it lists the plugin folders by reading the copy's `site/wp-content/plugins` folder, not by asking WordPress, and it runs no `plugin list` and nothing that sets a transient. Refresh it whenever `theme.json` changes, or WordPress or Gutenberg on the site moves, and commit the three files. When the fixture was made from another `theme.json` than the folder's, or is missing, the harness stops with the refresh command; a WordPress or Gutenberg update is not detected (compare the versions in `global-styles.json` with the site's). A theme with a `styles/` folder of variations is refused. `bin/test-ui-layout.php` proves the page carries the fixture for the theme it is given, that a theme button in a drawing computes to theme.json's button look, and that a stale fixture stops the page; it needs no Docker and no network.
13. What the harness proves: that every case at every main-area width fits its box, with the plugin's sheets, WordPress's global styles and block library sheets and the theme's sheets in the site's order, on the dashboard page's body classes and wrappers; and the computed look of elements those sheets decide (fonts, colors, the theme's buttons and links, sizes and gaps).
14. What still needs a real page: anything a script does (the frame's folding menu, the parts' panels opening, the type-and-pick boxes, a script's own markup); the WordPress toolbar (its 32px and the `admin-bar` body class are not drawn); the site's WordPress.org header and footer and the frame's side menu (left out of every pass); the layout styles WordPress generates per rendered block (`core-block-supports`) and the styles of blocks the header, the footer or a page's content render (navigation, search and the like); the global styles of plugins' blocks other than Gutenberg's; real data (names, counts, lengths the suites did not draw); and the fonts and window sizes of a reader's own browser.
