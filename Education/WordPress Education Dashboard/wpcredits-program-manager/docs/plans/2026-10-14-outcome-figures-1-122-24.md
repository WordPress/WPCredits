# Release 1.122.24: the live outcome figures, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The plugin counts the three outcome figures the Education Hub homepage will show, the share of WordPress Credits students who graduate rather than drop out, the share of graduates who would recommend the program and the share who plan to keep contributing, with the public impact dashboard's own definitions; reads them every Monday after the dashboard's build; stores them with their counts and the time they were read, never from a failed or suspicious read; says how the last read went on the syncs row of the Overview and the Administrator Dashboard; and hands the theme what may be shown through one function. Nothing public changes in this release.

**Architecture:** One new class, `WPCPM_Outcome_Figures` (`includes/class-wpcpm-outcome-figures.php`), booted with the plugin's other services. `compute()` is a pure function from Airtable's rows to the figures and holds the definitions alone; `refresh()` reads two tables through `WPCPM_Airtable` with fields by ID, guards, and stores two options; `published()` is what the theme reads; `status()` and `sync_row()` serve the syncs row; `field_names()` and `stored()` serve WP-CLI. Two additive changes to the shared client (`fetch_page()`'s `by_id`, `fetch_schema()`'s `ids`), one row in `WPCPM_Administrators_Cards::health()`, one line in the Overview's syncs table, and one WP-CLI command, `wp wpcredits outcome_figures`.

**Tech Stack:** WordPress 7.1 plugin PHP (7.4 and 8.x); the plugin's `bin/test-*.php` suites, plain PHP with their own stand-ins; `WPCPM_Airtable` (`fetch_page()`, `fetch_schema()`, `formula_in()`, its pacing and shared 429 back-off), `WPCPM_Settings`, `WPCPM_Settings_Screen::settings_url()`, `WPCPM_Administrators_Cards::health()` and `render_health()`, `WPCPM_Overview::render_syncs()`, `WPCPM_CLI`; WordPress cron (the `weekly` recurrence and single events); `wp_safe_remote_get()` for the dashboard's page; WP-CLI for the translation template.

**Spec:** `docs/specs/2026-10-14-education-hub-homepage-design.md`, the owner's approval of 14 October 2026; this plan carries out its sections 5.1, 5.3 (item 1), 8, 9 and 10.1, and leaves 10.2 (the parity check on the live site) to the owner's yes after the deploy. The theme's plan, `docs/plans/2026-10-14-education-hub-theme-1-24-15.md`, reads the figures through `WPCPM_Outcome_Figures::published()` (Task 2's Interfaces block names it and its return shape).

**Base:** main at fd3f998, the merge of 1.122.23 (f43d54a, its final fix wave), live on 14 October 2026; fd3f998 differs from f43d54a by the spec alone. Every anchor below is that commit's text, and the release's branch starts from it.

**Order:** the definitions (Task 1); the read, the guards and what may be shown, with the client's `by_id` (Task 2); the weekly event, the wait for the dashboard's build and the retries, with the plugin's boot, activation, deactivation and uninstall (Task 3); the syncs row (Task 4); WP-CLI and the field names (Task 5); the guide, the version, the changelog and the template (Task 6).

**Where the spec left a choice, this plan chooses:**

- **The graduation share is rounded exactly as the dashboard's page rounds it,** `Math.round( grad / finished * 100 )`: the division first, in floating point, then half up on what it gives, so a share that is a half in whole numbers can land just under it (23 of 40 is 57.49999999999999, and 57). Rounding the exact fraction half up would give 58 there, and differs from the page in 80 of the 2,003,000 pairs of a count and an n up to 2,000; the page's own expression never differs, so the homepage and the dashboard never differ by a point. The two survey shares are rounded half to even, as the build's `round()` in `_pct_positive()` rounds them.
- **`published()` also leaves out a figure whose numerator is zero.** Guard 2 never stores one; the check in `published()` is for a set written some other way, so success criterion 5's "never a zero" holds whatever the option holds. A set in any other shape than the one a run writes (a read time or a share that is not a whole number, a share over 100, a count over its n, a figure missing) is no set: nothing is shown from it and nothing is compared with it.
- **`--accept` skips guards 3 and 4, never guard 2.** It is for a run the comparison held, once a person has checked the counts; a zero is "almost always a renamed status or choice" (8.5), which a person accepting would be accepting by mistake.
- **A run that waits is recorded too,** with result `waiting` and reason `dashboard`, beside 8.4's `stored`, `held` and `failed`, since the syncs row says "Waiting for the dashboard's Monday build" (section 9). The run option also keeps the attempt's Monday (`monday`, its UTC date) and the tries recorded for it (`tries`), 8.4's "how many tries that Monday has made".
- **Retries are booked at whole hours,** 08:00 to 12:00 UTC, so the last is the 12:00 UTC try whatever minute the 07:00 event fired at, as a single event of its own, `wpcpm_outcome_figures_retry`, so the weekly event's drift check never reads a retry as the weekly time. A run at or after 12:00 UTC that Monday, or on a later day of the week (a late cron), is the last try: it reads Airtable without reading the dashboard's page, and books nothing. A held or stored run takes a booked retry off. A scheduled run that finds another read running (a parity check from WP-CLI, say) books the next hour's try as a failed one does, the last at 12:00 UTC, rather than leaving the Monday without a read. A run from WP-CLI never waits and never books.
- **The dashboard's build date** is `"builtAt":"Y-m-d"` in the `const D = {...}` its page carries (read on 14 October 2026: `const D = {"builtAt":"2026-10-12","global":{...`). A date on or after the run's Monday is a build; an older date makes a run before 12:00 UTC wait; a page that cannot be read, answers anything but 200, or holds no such date is no reason to wait.
- **The formula filters on the status column by name,** the one the mentors and students syncs filter on every three hours (`WPCPM_Mentors_Sync::fields()['report_status']`, "Status", filterable by `wpcpm_mentors_fields`), as 8.2 says ("filtered with `formula_in()` on the Status column"); everything else reads field IDs. A renamed column fails the read (Airtable's 422), which the syncs row says.
- **A table still paging after 50 pages fails the run,** and nothing is counted from part of it (criterion 5: never "a figure from an incomplete ... read"); Students Reports is about five pages and Feedback about nine.
- **`fetch_schema()` gains `ids`,** each table's field names by field ID, a second additive change to the client beside `by_id`: the parity check prints "the name the base gives each of the four pinned field IDs (from the base's table metadata)" (10.2), and the schema read kept fields by name alone. Every key a table entry held is as it was.
- **The syncs row is in the shape every sync's row has,** with one key more, `note`: the Overview prints it on a line of its own under the row's last run, and the Administrator Dashboard's card, whose renderer is not changed, prints `progress['error']`, which holds the same sentence. Its last run is when the stored set was read, so a held or failed attempt never reads as a fresh figure; its next run is the earlier of a booked retry and the weekly event; while a run holds the lock the row is running, "Reading Airtable".
- **The sentences an Administrator reads,** each worded at the run in the site's language: "Not connected."; "Waiting for the dashboard's Monday build."; "Failed: Airtable refused the token." (401, 403); "Failed: Airtable asked the site to wait." (429); "Failed: " and the error's own sentence (a 404 or 422 with Airtable's message, a 5xx, a timeout, an answer that is not JSON, a table paging past 50 pages); "Held: no graduates were counted." (and the two survey numerators: "answers of likely to recommend", "answers of likely to keep contributing"); "Held: graduates fell from 361 to 324, by more than 10%." (and "students who graduated or dropped out", "answers to the recommend question", "answers to the keep-contributing question"); "Held: the graduation share moved from 87% to 76%, by more than 10 points." (and "the would-recommend share", "the keep-contributing share"); and, for a stored set with a figure under the minimum, "Not shown on the homepage, with fewer than 30 answers or outcomes: the would-recommend share (12)."
- **`wpcpm_outcome_figures_max_age` filters days** (29), as decision 10 speaks of the limit; `wpcpm_outcome_figures_min_sample` filters the n (30).
- **WP-CLI:** with no option it reports the stored set, what the homepage may show and the last attempt, and reads nothing; `--dry-run` and `--accept` go with `--refresh`, and not together; a held read prints its counts and exits non-zero, saying `--refresh --accept` stores it once checked.
- **The guide:** the Overview section's syncs paragraph gains one sentence on the fifth row, naming each note the row can show (why the last attempt was held or failed, the wait for the dashboard's build, "Not connected.", and a figure left out for having fewer than 30 answers or outcomes), and its "The table shows no errors" becomes "The audiences' rows show no errors", so the paragraph stays true.

## Review Focus

1. **A Status or an answer cell in a shape the dashboard does not count** (a list, a number, null, an object with a name, a record with no fields or fields that are not a list): counted exactly as the dashboard's `status_key()` counts it, a string or a select's `name` alone, and never a crash. Pinned in Task 1 (`bin/test-outcome-figures.php`, the definitions).
2. **A table that keeps paging, or an answer that is not JSON:** the run fails with its sentence and stores nothing, never a count over part of a table. Pinned in Task 2 (the 50-page cap; "an answer not in JSON" among the failures).
3. **Two runs at once, the weekly event and WP-CLI, or a run killed halfway that left its lock:** the second reads nothing and says another read is running; a lock older than ten minutes is taken over, and every run gives its lock back, failed or not. A scheduled run that finds the lock held tries again an hour later, the last try at 12:00 UTC. Pinned in Task 2, and the scheduled run's retry in Task 3.
4. **The stored option in another shape than a run writes:** a string, no read time or one as a string, a figure missing, a share over 100 or as a string or null, a count over its n, a negative n: nothing is shown from it and nothing is compared with it. Pinned in Task 2 (`published()`), and the syncs row reads it the same way in Task 4.
5. **The dashboard's page unreachable, answering 404 or 503, carrying no `builtAt` or one with a time, or not the dashboard at all; a cron that fires late on Tuesday, or after 12:00 UTC:** the run reads Airtable at once rather than waiting on a page that will never say yes. Pinned in Task 3.

/**
 * One check.
 *
 * @param string $label    What is asked.
 * @param mixed  $actual   What happened.
 * @param mixed  $expected What should have happened.
 */
function ck( $label, $actual, $expected ) {
	global $fail, $total;

	++$total;

	$ok = $actual === $expected;

	if ( ! $ok ) {
		++$fail;
	}

	echo ( $ok ? 'ok   ' : 'FAIL ' ) . $label . "\n";

	if ( ! $ok ) {
		echo '       expected: ' . var_export( $expected, true ) . "\n";
		echo '       actual:   ' . var_export( $actual, true ) . "\n";
	}

/**
 * A Students Reports record as Airtable sends it with fields by ID.
 *
 * @param int   $i      Which record, for its invented ID.

 * @param mixed $status The status cell, or the string 'absent'.
 * @return array
 */
function report( $i, $name, $status ) {
	$fields = array();

	if ( 'absent' !== $name ) {
		$fields[ WPCPM_Outcome_Figures::FIELD_NAME ] = $name;
	}

	if ( 'absent' !== $status ) {
		$fields[ WPCPM_Outcome_Figures::FIELD_STATUS ] = $status;
	}

	return array(
		'id'     => sprintf( 'recREPORT%08d', $i ),
		'fields' => $fields,
	);
}

 * Records of one shape, many times over.
 *
 * @param int      $times How many.
 * @param callable $make  Builds record $i.
 * @return array[]

function many( $times, $make ) {
	$records = array();

	for ( $i = 0; $i < $times; $i++ ) {
		$records[] = $make( $i );
	}

	return $records;
}

<?php
/**
 * The program's three outcome figures, counted by the site with the public dashboard's definitions.
 *
 * @package WPCreditsProgramManager
 */

if ( ! defined( 'ABSPATH' ) ) {
	exit;
}

/**
 * The graduation share, the share of graduates who would recommend the program and the share who
 * plan to keep contributing, read from Airtable once a week and stored with their counts and the
 * time they were read.
 *
 * **The definitions are the public impact dashboard's, exactly.** That dashboard,
 * https://wordpress.github.io/WPCredits/, is built from the same base by WordPress/WPCredits'
 * `scripts/build_dashboard.py` and `scripts/template.html`; a figure on the site's homepage that
 * disagreed with it, even by its rounding, would be one of the two telling a reader something
 * wrong. So `compute()` holds the definitions and nothing else: the field IDs the dashboard reads,
 * the statuses and answers it counts, the way it reads a cell (a select's name, trimmed and
 * lowercased), the way it decides a student record is there at all (its name is present and not the
 * empty string, as Python's `if not name` decides), and how each share is rounded (the graduation
 * share as the page's `Math.round( grad / finished * 100 )` rounds it, the division first; the two
 * survey shares half to even, as Python's `round()` in `_pct_positive()` does). It is a pure function from Airtable's rows to the figures,
 * tested on fixtures, so the day the program's records move onto the site only the reader changes.
 *
 * Each figure carries its own denominator. A Feedback row is created for every student whether or
 * not they ever answer, so the rows are never the denominator: a survey share is over the answers to
 * its own question.
 */
final class WPCPM_Outcome_Figures {

	/**
	 * Students Reports: the student's name, read only to test that it is there.
	 *
	 * The four field IDs are the dashboard's own, pinned as it pins them, so the figures read the same
	 * columns whatever the columns are called.
	 *
	 * @var string
	 */
	const FIELD_NAME = 'fldyXVlkChJaO9Q47';

	/**
	 * Students Reports: the student's status, a single select.
	 *
	 * @var string
	 */
	const FIELD_STATUS = 'fldCMdqqJGAUQ9nbV';

	/**
	 * Feedback: how likely the student is to recommend the program, a single select on the final
	 * survey.
	 *
	 * @var string
	 */
	const FIELD_RECOMMEND = 'fldZXbvOTIGad6r90';

	/**
	 * Feedback: how likely the student is to keep contributing to WordPress, a single select on the
	 * final survey.
	 *
	 * @var string
	 */
	const FIELD_KEEP = 'fld8RZMdCLYKtwcLN';

	/**
	 * The status a graduate holds, as the dashboard compares it: trimmed and lowercased.
	 *
	 * @var string
	 */
	const GRADUATE = 'graduate';

	/**
	 * The status a student who dropped out holds, compared the same way.
	 *
	 * @var string
	 */
	const DROPPED_OUT = 'dropped out';

	/**
	 * The one survey answer that counts as yes, compared the same way. "Neither likely nor unlikely"
	 * and "Unlikely" count among the answers only.
	 *
	 * @var string
	 */
	const POSITIVE = 'likely';

	/**
	 * The three figures, in the order the homepage shows them.
	 *
	 * @var string[]
	 */
	const FIGURES = array( 'graduation', 'recommend', 'keep' );

	/**
	 * The three figures from Airtable's rows.
	 *
	 * @param array[] $reports  Students Reports records as Airtable returns them with fields by ID:
	 *                          each `array( 'id' => ..., 'fields' => array( field ID => value ) )`.
	 * @param array[] $feedback Feedback records, the same shape.
	 * @return array<string, array{share: int|null, count: int, n: int}> `graduation`, `recommend` and
	 *                                                                    `keep`, each its share (null
	 *                                                                    when nothing was counted), its
	 *                                                                    numerator and its n.
	 */
	public static function compute( array $reports, array $feedback ) {
		$graduates = 0;
		$dropouts  = 0;

		foreach ( $reports as $record ) {
			$fields = self::fields_of( $record );

			if ( ! array_key_exists( self::FIELD_NAME, $fields ) || ! self::truthy( $fields[ self::FIELD_NAME ] ) ) {
				continue;
			}

			$status = self::key( isset( $fields[ self::FIELD_STATUS ] ) ? $fields[ self::FIELD_STATUS ] : null );

			if ( self::GRADUATE === $status ) {
				++$graduates;
			} elseif ( self::DROPPED_OUT === $status ) {
				++$dropouts;
			}
		}

		$n = $graduates + $dropouts;

		return array(
			'graduation' => array(
				'share' => $n > 0 ? self::half_up( $graduates, $n ) : null,
				'count' => $graduates,
				'n'     => $n,
			),
			'recommend'  => self::answers( $feedback, self::FIELD_RECOMMEND ),
			'keep'       => self::answers( $feedback, self::FIELD_KEEP ),
		);
	}

	/**
	 * One survey figure: the answers to one question that are not empty, and the ones among them that
	 * are the positive answer.
	 *
	 * @param array[] $feedback Feedback records.
	 * @param string  $field    The question's field ID.
	 * @return array{share: int|null, count: int, n: int}
	 */
	private static function answers( array $feedback, $field ) {
		$positive = 0;
		$answered = 0;

		foreach ( $feedback as $record ) {
			$fields = self::fields_of( $record );
			$answer = self::key( isset( $fields[ $field ] ) ? $fields[ $field ] : null );

			if ( '' === $answer ) {
				continue;
			}

			++$answered;

			if ( self::POSITIVE === $answer ) {
				++$positive;
			}
		}

		return array(
			'share' => $answered > 0 ? self::half_even( $positive, $answered ) : null,
			'count' => $positive,
			'n'     => $answered,
		);
	}

	/**
	 * A record's fields, or none when the record is not the shape Airtable sends.
	 *
	 * @param mixed $record One record.
	 * @return array
	 */
	private static function fields_of( $record ) {
		return is_array( $record ) && isset( $record['fields'] ) && is_array( $record['fields'] ) ? $record['fields'] : array();
	}

	/**
	 * A select cell as the dashboard's `status_key()` reads it: the option's name, from a plain string
	 * or from an object holding a `name`, trimmed and lowercased; '' for anything else, a list, a
	 * number or nothing at all.
	 *
	 * @param mixed $value The cell.
	 * @return string
	 */
	private static function key( $value ) {
		if ( is_array( $value ) && array_key_exists( 'name', $value ) ) {
			$value = $value['name'];
		}

		if ( ! is_string( $value ) ) {
			return '';
		}

		return strtolower( trim( $value ) );
	}

	/**
	 * Whether a cell counts as there, the way Python's `if not name` decides: anything but nothing,
	 * false, a zero, the empty string, an empty list and an empty object. A name of one space is there:
	 * the dashboard does not trim it.
	 *
	 * @param mixed $value The cell, as `json_decode()` gave it.
	 * @return bool
	 */
	private static function truthy( $value ) {
		return ! ( null === $value || false === $value || 0 === $value || 0.0 === $value || '' === $value || array() === $value );
	}

	/**
	 * The share count / n x 100, rounded as the dashboard's page rounds it: `Math.round( grad /
	 * finished * 100 )`, the division made first in floating point, so a share that is a half in whole
	 * numbers can land just under it (23 of 40 is 57.49999999999999, and 57). The expression is the
	 * page's own, half up on the float JavaScript computes, so the homepage and the dashboard never
	 * differ by a point.
	 *
	 * @param int $count The numerator.
	 * @param int $n     The denominator, above 0.
	 * @return int
	 */
	private static function half_up( $count, $n ) {
		$share = $count / $n * 100;
		$whole = floor( $share );

		return (int) ( $share - $whole >= 0.5 ? $whole + 1 : $whole );
	}

	/**
	 * 100 x count / n, rounded half to even, as Python's `round()` rounds: 12.5 is 12 and 87.5 is 88.
	 *
	 * @param int $count The numerator.
	 * @param int $n     The denominator, above 0.
	 * @return int
	 */
	private static function half_even( $count, $n ) {
		$whole = intdiv( 100 * $count, $n );
		$left  = 100 * $count - $whole * $n;

		if ( 2 * $left > $n || ( 2 * $left === $n && 1 === $whole % 2 ) ) {
			++$whole;
		}

		return $whole;
	}
}

function wp_remote_request( $url, $args = array() ) {

		$read = self::read( $settings );

		if ( is_wp_error( $read ) ) {
			list( $reason, $message ) = self::failure( $read );

			if ( empty( $args['dry_run'] ) ) {
				self::record( $now, 'failed', $reason, $message, array() );
			}

			return self::result( 'failed', $reason, $message );
		}

	 * `MAX_PAGES`: a count over part of a table is never made.
	 *
	 * @param WPCPM_Airtable $airtable The client.
	 * @param string         $table    The table ID.
	 * @param array          $args     What `fetch_page()` is asked, the offset aside.
	 * @return array|WP_Error The records.
	 */
	private static function read_all( WPCPM_Airtable $airtable, $table, array $args ) {
		$records = array();
		$offset  = null;
		$pages   = 0;

		do {
			if ( $pages >= self::MAX_PAGES ) {
				return new WP_Error(
					'wpcpm_outcome_pages',
					/* translators: %d: the most pages one table is read in. */
					sprintf( __( 'Airtable was still paging after %d pages, so nothing was counted.', 'wpcredits-program-manager' ), self::MAX_PAGES )
				);

			$args['offset'] = $offset;
			$page           = $airtable->fetch_page( $table, $args );

			if ( is_wp_error( $page ) ) {
				return $page;
			}

			$records = array_merge( $records, $page['records'] );
			$offset  = $page['offset'];
			++$pages;
		} while ( null !== $offset && '' !== $offset );

		return $records;

	 * trip holds the run. The first run on a site has nothing to compare with, and `$accept` skips the
	 * comparison; a zero is held either way.
	 *
	 * @param array $figures What `compute()` counted.
	 * @param mixed $stored  The stored set, as the option holds it.
	 * @param bool  $accept  Whether a person has checked the set.
	 * @return string[] The reason code and its sentence, both '' when every guard holds.
	 */
	private static function guard( array $figures, $stored, $accept ) {
		$names = self::names();

		foreach ( self::FIGURES as $key ) {
			if ( 0 === (int) $figures[ $key ]['count'] ) {
				return array(
					'zero',
					/* translators: %s: what was counted, such as "graduates". */
					sprintf( __( 'Held: no %s were counted.', 'wpcredits-program-manager' ), $names[ $key ]['count'] ),
				);
			}
		}

		if ( $accept || ! self::is_set( $stored ) ) {
			return array( '', '' );
		}

		foreach ( self::FIGURES as $key ) {
			foreach ( array( 'count', 'n' ) as $part ) {
				$before = (int) $stored[ $key ][ $part ];
				$after  = (int) $figures[ $key ][ $part ];

				if ( 100 * $after < ( 100 - self::MAX_FALL ) * $before ) {
					return array(
						'fell',
						sprintf(
							/* translators: 1: what was counted, such as "graduates", 2: the stored count, 3: the count read now. */
							__( 'Held: %1$s fell from %2$s to %3$s, by more than 10%%.', 'wpcredits-program-manager' ),
							$names[ $key ][ $part ],
							number_format_i18n( $before ),
							number_format_i18n( $after )
						),
					);
				}
			}
		}

			$before = (int) $stored[ $key ]['share'];
			$after  = (int) $figures[ $key ]['share'];

	/**
	 * A failed read's reason code and sentence: Airtable refusing the token (401, 403), asking the
	 * site to wait (429), refusing the request (404, 422 or another 4xx, with Airtable's message), a
	 * table paging past `MAX_PAGES`, or anything else (a timeout, a 5xx, an answer that is not JSON).
	 *
	 * @param WP_Error $error What the read failed with.
	 * @return string[] The reason code and its sentence.
	 */
	private static function failure( WP_Error $error ) {
		$data   = (array) $error->get_error_data();
		$status = isset( $data['status'] ) ? (int) $data['status'] : 0;

		if ( 401 === $status || 403 === $status ) {
			return array( 'refused', __( 'Failed: Airtable refused the token.', 'wpcredits-program-manager' ) );
		}

		if ( 429 === $status ) {
			return array( 'rate_limited', __( 'Failed: Airtable asked the site to wait.', 'wpcredits-program-manager' ) );
		}

		if ( 'wpcpm_outcome_pages' === $error->get_error_code() ) {
			$reason = 'pages';
		} elseif ( $status >= 400 && $status < 500 ) {
			$reason = 'airtable';
		} else {
			$reason = 'unreachable';
		}

		/* translators: %s: the error's own sentence. */
		return array( $reason, sprintf( __( 'Failed: %s', 'wpcredits-program-manager' ), $error->get_error_message() ) );
	}

	/**
	 * Write the attempt: its time, result, reason, sentence and the counts it saw, nothing else.
	 *
	 * @param int    $now     The run's time.
	 * @param string $result  `stored`, `held` or `failed`.
	 * @param string $reason  The reason code.
	 * @param string $message Its sentence.
	 * @param array  $figures What `compute()` counted, or none.
	 */
	private static function record( $now, $result, $reason, $message, array $figures ) {
		update_option(
			self::RUN_OPTION,
			array(
				'time'    => (int) $now,
				'result'  => $result,
				'reason'  => $reason,
				'message' => $message,
				'counts'  => self::counts_of( $figures ),
			),
			false
		);
	}

	/**
	 * Each figure's numerator and n, the counts a run keeps of what it saw.
	 *
	 * @param array $figures What `compute()` counted, or none.
	 * @return array<string, array{count: int, n: int}>
	 */
	private static function counts_of( array $figures ) {
		$counts = array();

		foreach ( self::FIGURES as $key ) {
			if ( isset( $figures[ $key ]['count'], $figures[ $key ]['n'] ) ) {
				$counts[ $key ] = array(
					'count' => (int) $figures[ $key ]['count'],
					'n'     => (int) $figures[ $key ]['n'],
				);
			}
		}

		return $counts;
	}

	/**
	 * What `refresh()` returns.
	 *
	 * @param string $result  The result.
	 * @param string $reason  The reason code.
	 * @param string $message Its sentence.
	 * @param array  $figures What was counted.
	 * @param array  $rows    The rows each read returned.
	 * @return array
	 */
	private static function result( $result, $reason, $message, array $figures = array(), array $rows = array() ) {
		return array(
			'result'  => $result,
			'reason'  => $reason,
			'message' => $message,
			'figures' => $figures,
			'rows'    => $rows,
		);
	}

	/**
	 * Whether a stored set is whole: its read time, and each figure's share, numerator and n as whole
	 * numbers that make sense together. A set the option holds in any other shape is no set: nothing
	 * is shown from it and nothing is compared with it.
	 *
	 * @param mixed $set The option's value.
	 * @return bool
	 */
	private static function is_set( $set ) {
		if ( ! is_array( $set ) || ! isset( $set['read'] ) || ! is_int( $set['read'] ) || $set['read'] <= 0 ) {
			return false;
		}

		foreach ( self::FIGURES as $key ) {
			$figure = isset( $set[ $key ] ) && is_array( $set[ $key ] ) ? $set[ $key ] : array();

			foreach ( array( 'share', 'count', 'n' ) as $part ) {
				if ( ! isset( $figure[ $part ] ) || ! is_int( $figure[ $part ] ) || $figure[ $part ] < 0 ) {
					return false;
				}
			}

			if ( $figure['share'] > 100 || $figure['count'] > $figure['n'] ) {
				return false;
			}
		}

		return true;
	}

	/**
	 * Take the lock, or say another run holds it. A lock older than `LOCK_TTL` was left by a run that
	 * never finished, and is taken over.
	 *
	 * @param int $now The run's time.
	 * @return bool
	 */
	private static function lock( $now ) {
		if ( add_option( self::LOCK_OPTION, (int) $now, '', false ) ) {
			return true;
		}

		$held = (int) get_option( self::LOCK_OPTION, 0 );

		if ( $held > 0 && $now - $held < self::LOCK_TTL ) {
			return false;
		}

		update_option( self::LOCK_OPTION, (int) $now, false );

		return true;
	}

	/**
	 * Give the lock back.
	 */
	private static function unlock() {
		delete_option( self::LOCK_OPTION );
	}

	/**
	 * The current Unix time.
	 *
	 * @return int
	 */
	private static function now() {
		return null !== self::$clock ? (int) call_user_func( self::$clock ) : time();
	}
}

### Task 3: The weekly event, the wait for the dashboard's build, and the retries

The figures are read every Monday at 07:00 UTC, on WordPress's `weekly` recurrence: scheduled on activation, checked on `init` and put back when it has drifted, cleared on deactivation and on uninstall. 	/**
	 * Show the outcome figures the site counts for its homepage, or read them again from Airtable.
	 *
	 * With no option, prints the stored set, when it was read, what the homepage may show of it, and
	 * the last attempt. The weekly event reads the figures every Monday after the public dashboard's
	 * build; --refresh reads them at once, without waiting for it.
	 *
	 * ## OPTIONS
	 *
	 * [--refresh]
	 * : Read Airtable now, and store the figures when every guard holds.
	 *
	 * [--dry-run]
	 * : With --refresh: print the counts and the name the base gives each of the four field IDs, and store nothing.
	 *
	 * [--accept]
	 * : With --refresh: store the figures although they fell or moved more than the guards allow, once a person has checked them.
	 *
	 * ## EXAMPLES
	 *
	 *     wp wpcredits outcome_figures
	 *     wp wpcredits outcome_figures --refresh --dry-run
	 *     wp wpcredits outcome_figures --refresh
	 *     wp wpcredits outcome_figures --refresh --accept
	 *
	 * @param array $args       Positional arguments.
	 * @param array $assoc_args Associative arguments.
	 */
	public function outcome_figures( $args, $assoc_args ) {
		unset( $args );

		$refresh = ! empty( $assoc_args['refresh'] );
		$dry_run = ! empty( $assoc_args['dry-run'] );
		$accept  = ! empty( $assoc_args['accept'] );

		if ( ( $dry_run || $accept ) && ! $refresh ) {
			WP_CLI::error( '--dry-run and --accept go with --refresh.' );
		}

		if ( $dry_run && $accept ) {
			WP_CLI::error( 'Use --dry-run or --accept, not both.' );
		}

		if ( ! $refresh ) {
			$this->outcome_figures_stored();

			return;
		}

		$run = WPCPM_Outcome_Figures::refresh(
			array(
				'dry_run' => $dry_run,
				'accept'  => $accept,
			)
		);

		if ( 'not_connected' === $run['result'] ) {
			WP_CLI::error( 'Airtable is not configured.' );
		}

		if ( in_array( $run['result'], array( 'busy', 'failed' ), true ) ) {
			WP_CLI::error( $run['message'] );
		}

		$this->outcome_figures_counts( $run );

		if ( $dry_run ) {
			$names = WPCPM_Outcome_Figures::field_names();

			if ( is_wp_error( $names ) ) {
				WP_CLI::warning( sprintf( 'The base\'s names for the four fields could not be read: %s', $names->get_error_message() ) );

					WP_CLI::log( sprintf( '%-20s %s', $id, '' === $name ? '(not in its table)' : $name ) );
				}

			WP_CLI::success( 'Dry run complete - nothing was stored.' );

			return;
		}

			WP_CLI::error( $run['message'] . ' Nothing was stored. Once the counts above are checked, --refresh --accept stores them.' );
		}
