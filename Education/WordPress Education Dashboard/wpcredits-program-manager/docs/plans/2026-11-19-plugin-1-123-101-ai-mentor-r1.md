# Plugin 1.123.101: AI Mentor R1, the answering engine behind Need help? (implementation plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Need help? answers from the site's own guides, the FAQ and the synced WordPress Credits handbook: an index of passages on the site, ranked by their words, and a short answer the model writes from the best five, in the asker's language, with a link to each passage it used; the Gemini web-search path and the plugin's own key are gone.

**Architecture:** Four new classes in `includes/tools/`: `WPCPM_Guide_Text` (passages and terms, no database, no WordPress), `WPCPM_Guide_Index` (the two tables), `WPCPM_Guide_Search` (BM25, the one ranking function) and `WPCPM_Guide_Sources` (which pages, who may read them, the handbook sync, every reindex trigger). `WPCPM_Handbook_Answer` keeps its name and its answer's shape and is rewritten on top of them and the WordPress AI Client; the panel, the shortcode, the Ask box and the tool screen keep their places.

**Tech Stack:** PHP 7.4+ WordPress plugin `wpcredits-program-manager` (prefix `WPCPM_`); the WordPress AI Client in core (7.0 and later: `wp_ai_client_prompt()`, `WP_AI_Client_Prompt_Builder`, `WordPress\AiClient\AiClient::defaultRegistry()`) with a provider from Settings > Connectors; the no-WordPress suites `bin/test-*.php` (run from the plugin root, each ends `ALL PASS` and exits 0) and their SQLite stand-in of the database (`bin/stubs/sqlite-wpdb.php`); the Docker copy in `~/Projects/wpcredits-docker`; the release script `~/Projects/wpcredits-release/release.py`.

**Spec:** `docs/specs/2026-11-19-ai-mentor-r1-answering-engine-design.md`. It is the binding authority: read all of it before any task. Sections 3 to 13 are what this plan builds, section 17's anti-goals are what the tests guard, section 18 lists the calls the product owner still checks.

## Rulings

Where the design leaves a detail open, the plan rules here, once; each task that builds a ruling names it.

1. **Base, number, branch.** Built on main at 1.123.99 (`e626f932` or later) as **1.123.101**: 1.123.100 is reserved for Institutions release 2, and whichever deploys second re-bumps past the then-live version. Branch `feature/ai-mentor-r1`, worktree `.worktrees/ai-mentor-r1`. Commit messages start `AI Mentor R1:`.
2. **The test set comes first.** `bin/test-guide-questions.php` and its two fixtures are the branch's first commit, written by the coordinator before Task 1. They fail until Task 2 lands, and pass from then on; a task never edits a question's expected page or section to make the set pass. A failing question is fixed in the text pipeline or the ranking, or reported to the coordinator as a wrong expectation, with the passage that proves it.
3. **Fixtures.** `bin/fixtures/guides/faq.json` holds the FAQ page (page 2746) as its REST route answers (`id`, `link`, `title`, `modified_gmt`, `content`), and `bin/fixtures/guides/handbook.json` the handbook route's answer: the twelve kept pages whole, plus one page under `program-manager-guide/` and one under `campus-connect/` with their content cut to a paragraph, so the keep filter is tested on the route's own shape. Every email address in both is replaced by `address@example.test` (the mirror's scan refuses others). The built guides are read from `docs/build/*.html`.
4. **The index boots with the plugin, not with the tool.** `WPCPM_Guide_Sources::init()` is called from `wpcpm_bootstrap()` right after `WPCPM_Mail_Log::init()`, so the ability and the CLI find the index whether or not Need help? is switched on. Activation calls `WPCPM_Guide_Sources::activate()` (tables, then one rebuild scheduled), deactivation `deactivate()` (both events cleared), uninstall `uninstall()` (both tables dropped, the three options deleted).
5. **Audiences.** A passage's `audience` is one of `student`, `mentor`, `institution`, `sponsor`, `administrator`, `public`. A page's audience is fixed by its path (`pages()`); who may read it is `WPCPM_Content_Access::can_view( $page, $user )`, asked of the page when the question is asked. The handbook and the FAQ are `public`. An asker always reads `public`.
6. **The home guide.** `home_for( $user, $asked )`: `$asked` when it is one of the five and the asker reads that audience; otherwise the first of administrator (holds `WPCPM_Roles::CAP_MANAGE`), sponsor, institution, mentor, student whose audience the asker reads; otherwise `''`.
7. **Links.** A site passage's `url` is `get_permalink( $page )` plus `#<anchor>` when the passage has one; a handbook passage's is the page's REST `link`. Both pass through `esc_url_raw()` in `WPCPM_Guide_Index::write()`, and a passage whose address does not survive is not written.
8. **The model.** `handbook_model` (default `gemini-flash-latest`) is looked up by name in each configured provider (`AiClient::defaultRegistry()`: `getRegisteredProviderIds()`, `isProviderConfigured()`, `getProviderModel()`), in the registry's order, and the first that offers it is used with `using_model()`. Never `using_model_preference()`, which falls back to the provider's first model. The lookup's outcome is kept in the transient `wpcpm_handbook_model_check` for twelve hours, keyed by the model name, and cleared when the setting is saved.
9. **The two calls** are made through `WPCPM_Handbook_Answer::call_model( $kind, $system, $prompt, $schema, $max_tokens, $timeout )` alone, where `$kind` is `words` or `answer`. `apply_filters( 'wpcpm_handbook_model_reply', null, $kind, $system, $prompt, $schema )` answers in the model's place when it returns a string or a `WP_Error`. Request options: timeout 15 seconds for `words`, 30 for `answer`; temperature 0.2; `as_json_response( $schema )`.
10. **A reply is JSON or it is a failure.** A reply is read with `json_decode()` after a surrounding Markdown code fence is taken off; anything that is not an object with the schema's keys and types is the failure `wpcpm_handbook_reply`. `cited` numbers outside 1 to the number of passages are dropped. Search words: at most twelve, each at most 40 characters.
11. **The fallback** is the three best passages, each with a 240-character excerpt, under one sentence naming why (spec section 6). With no search words, the ranking reads the question's own terms.
12. **Limits.** `within_limits()` and `count_use()` keep their transients (`wpcpm_hb_rate_<id>`, `wpcpm_hb_rate_day`) and `DAILY_CAP = 300`. A question is counted once it reaches the model (the first call made), and a question past a limit is answered with passages.
13. **Settings version 4.** `WPCPM_Settings::SETTINGS_VERSION` becomes 4; `maybe_upgrade()` deletes `handbook_provider` and `handbook_key` from a stored option once, and deletes the option `wpcpm_handbook_model_fixed`. `defaults()`, `sanitize()`, the `tool:handbook` scope and the Settings screen's secrets list lose the two keys.
14. **Words.** Every string a person reads: US English, plain hyphens, "Administrators", full product names, "Education Directory", "Need help?" for the tool. No string a mentor, a student, an institution or a sponsor sees says "AI Mentor". The footnote, the hint, the working line and the Sources heading are spec section 13's, word for word.
15. **Stand-ins.** A suite that reaches the AI Client stands in `wp_ai_client_prompt()` and the registry with a fake that records each call and answers from a script; no suite reaches the network.

## Review Focus

1. **A passage above the asker's level.** A student asking a mentor question ("How do I set my availability?") gets no Mentor guide passage; an institution's member never a Sponsor guide passage; only an Administrator an Administrator guide passage; a page made Administrators only after it was indexed is refused at once. Pinned in Task 2 and the test set.
2. **Instructions inside a passage or a question.** A guide or handbook passage that says "ignore the instructions" is quoted to the model inside the numbered list under the system instruction that passages are quotes; a reply that is not the schema's JSON (prose, a code fence around something else, extra keys of the wrong type) is a failure that falls back to passages. Pinned in Task 4.
3. **The model is down, busy, unset or misnamed.** No provider, a model no provider offers, a 429, a 503, a refused key, a timeout, an empty reply: each gives the passages and its own sentence, never a blank panel and never an exception. Pinned in Task 4.
4. **A save of an unrelated page, a draft, a revision, an autosave.** Only a published page at one of the six paths reindexes; a revision or an autosave of it never does; unpublishing it removes its passages. Pinned in Task 3.
5. **A handbook sync that fails halfway.** A timeout, a 500, a body that is not JSON, an empty list: the handbook's passages stay as they were and the state says when and why it failed. Pinned in Task 3.

### Task 1: Passages and terms

**Files:**
- Create: `includes/tools/class-wpcpm-guide-text.php`
- Test: `bin/test-guide-index.php` (new; this task writes its first part)

**Interfaces:**
- Produces `final class WPCPM_Guide_Text`, static, plain PHP with no WordPress function, so the suites load it bare:
  - `const PASSAGE_WORDS = 350;`
  - `stop_words(): array` the English stop words, `word => true` (the list Lucene's English analyzer uses, plus `can`, `do`, `does`, `how`, `i`, `my`, `what`, `when`, `where`, `which`, `who`, `why`, `you`, `your`).
  - `stem( string $word ): string`: Porter's algorithm, 1980, steps 1a to 5b, on a word of the letters a to z alone; a word with any other letter is returned as it is.
  - `terms( string $text ): string[]`: `mb_strtolower()`, split on `/[^\p{L}\p{N}]+/u`, words of one character and stop words dropped, each stemmed; order and repeats kept.
  - `counts( string $heading, string $body ): array<string, int>`: term => frequency, the heading's terms counted twice.
  - `plain( string $html ): string`: block comments, `script`, `style` and `svg` removed; block ends (`</p>`, `</li>`, `</h2>` to `</h6>`, `</summary>`, `</tr>`, `<br>`) become a newline; tags removed; entities decoded (`html_entity_decode( ENT_QUOTES | ENT_HTML5, 'UTF-8' )`); runs of spaces become one; lines trimmed; empty lines dropped.
  - `passages( string $html ): array`: a list of `array( 'heading' => string, 'anchor' => string, 'body' => string )`. A new passage starts at each `h2`, `h3`, `h4` and each `details` with an `id`; `heading` is the path of headings above it joined with ` > ` (a `details`' summary is one level below the heading it sits under); `anchor` is the heading's or the details' `id`, or `''`; `body` is `plain()` of what follows, up to the next start. A body over `PASSAGE_WORDS` words is split at line ends into parts of at most that many words (a single line over it at sentence ends, then at that many words), each part keeping the heading and anchor. A passage with an empty body is dropped.

- [ ] **Step 1: Write the failing tests** in `bin/test-guide-index.php`, part 1, among them:
  - `ck( 'Porter pairs', array_map( array( 'WPCPM_Guide_Text', 'stem' ), array( 'caresses', 'ponies', 'booking', 'booked', 'books', 'mentoring', 'mentors', 'graduation', 'graduated', 'relational', 'generalization' ) ), array( 'caress', 'poni', 'book', 'book', 'book', 'mentor', 'mentor', 'graduat', 'graduat', 'relat', 'gener' ) )`
  - `ck( 'stop words and one-letter words go', WPCPM_Guide_Text::terms( 'How do I book a call with my mentor?' ), array( 'book', 'call', 'mentor' ) )`
  - `ck( 'letters of any script are words', WPCPM_Guide_Text::terms( 'Cómo envío mi informe' ), array( 'cómo', 'envío', 'mi', 'inform' ) )` (Porter on a non-English word is harmless: the set's Spanish questions carry English search words)
  - `ck( 'a heading counts twice', WPCPM_Guide_Text::counts( 'Group sessions', 'A group session is booked.' ), array( 'group' => 3, 'session' => 3, 'book' => 1 ) )`
  - passages of a fixture `<h2 id="a">One</h2><p>x</p><h3 id="b">Two</h3><p>y</p><details id="q"><summary>Three?</summary><p>z</p></details>`: headings `One`, `One > Two`, `One > Two > Three?`, anchors `a`, `b`, `q`, bodies `x`, `y`, `z`.
  - a 900-word section gives three passages of at most 350 words, the same heading and anchor, nothing lost (the words joined equal the section's).
  - the built Student guide (`docs/build/students.html`) gives a passage `What is on your Student Report Card > Report form` with anchor `report-form`; the FAQ fixture gives `Before you apply > Do I need to know how to code?` with its details' id.

- Produces `final class WPCPM_Guide_Index`:
  - `SCHEMA_VERSION = 1`, `OPT_VERSION = 'wpcpm_guide_index_version'`, `OPT_STATE = 'wpcpm_guide_index_state'`.
  - `chunks_table(): string`, `terms_table(): string` (`$wpdb->prefix . 'wpcpm_guide_chunks'`, `... 'wpcpm_guide_terms'`); `schema(): string` (both `CREATE TABLE`s as `dbDelta()` reads them, the columns of spec section 4: `body` MEDIUMTEXT, `heading` and `title` VARCHAR(255), `url` VARCHAR(500), `term` VARCHAR(40), `hash` CHAR(32), `words` and `tf` SMALLINT UNSIGNED, the terms' primary key `(term,chunk_id)` and `KEY chunk_id`, the chunks' `KEY source` and `KEY hash`); `maybe_upgrade(): void`; `exists(): bool`; `drop(): void`.

- Produces `final class WPCPM_Guide_Search`:
  - `K1 = 1.2`, `B = 0.75`, `HOME = 1.25`; `weight( string $kind ): float` (`guide` and `faq` 1.0, `handbook` 0.8, through `apply_filters( 'wpcpm_guide_weight', $weight, $kind )`).

Empty words or audiences: `array()`.
