## Decisions this plan makes beyond the spec (rulings)

1. **The sponsors guide is published on the handbook, like the other three, and the button points at its handbook URL.** `guides()['sponsor']` becomes `label` "Sponsor guide", `url` `https://make.wordpress.org/community/handbook/education/credits/sponsor-guide/`; the channel and the chat label stay. The plugin ships no guide page: the three existing guides are composed by `bin/build-docs.php` into `docs/build/<audience>.html` and published on make.wordpress.org by hand, and this one follows them (the controller notes the hand step in the demonstration). Why not a site page: `docs/` never ships in the zip (`.distignore`), and a fourth guide is not the moment to add a page-publishing machine.
2. **The guide has four sections of its own, `40` to `43`, plus `00-signing-in`.** What the dashboard does (40), offers, codes and claims (41), what a sponsor can and cannot see (42), posts and how they are approved (43). No section of the mentor or student guides is repeated: a sponsor does not read the Student Report Card.
3. **"Offers running low" is the live pools under their own threshold, emptiest first, capped at `LIMIT`.** A pool is an offer of kind `codes` in state `live` whose last day has not passed (`is_live()`), and it is low when `WPCPM_Sponsor_Codes::counts()['available']` is below the offer's own `low` (the sponsor's number, the setting's default). A shared offer has no pool and is never low. The card links the offer to its sponsor's dashboard, at the Offers and codes card, through the switcher (`wpcpm_sponsor_view=<record>#wpcpm-sponsor-offers`), because that is where a manager acts on it.
4. **"New interests" are the audit rows of kind `sponsor_interest` from the last thirty days.** `WPCPM_Sponsor_Interests::handle_save()` records every expression of interest through `WPCPM_Institution_Audit::record_sponsor()` with `kind` `sponsor_interest` and the dated line as the message; the card reads `WPCPM_Institution_Audit::sponsor_entries( 'sponsor_interest', LIMIT )` and keeps the rows newer than thirty days. The message is printed as the sponsor wrote it, escaped, with the sponsor's name from the index and a link to the Interests card of its dashboard.
5. **The Sponsors strip is four figures on the programs card's tiles.** Approved sponsors (index rows whose `status` is `Approved`), with accounts (of those, the rows whose `dashboard_account` is true), live offers (`WPCPM_Sponsor_Offers::all()` filtered by `is_live()`), claims this semester (claims that stand, `v` empty, made at or after the first day of the current cohort, `WPCPM_Cohort::range( WPCPM_Cohort::current() )['from']`). It is its own card, `sponsors`, drawn with the `wpcpm-programs__tiles` markup the programs card uses for its tracks, so the theme dresses it already. Why a card and not a second attention strip: the attention strip is what needs a decision; these are figures.
6. **The twelfth attention tile is "Offers running low", last.** `counts()` gains `offers_low` after `sponsor_applications`, card `offers-low`. The suite's "eleven tiles" pins become twelve. Sponsor applications, pending posts and agreements to review are tiles already (S3, S4, S5).
7. **The full applications card is the compact card plus a folded "Read the application".** Each item gains a `<details class="wpcpm-administrator__details">` after its notes and before its decisions, whose body is `WPCPM_Sponsor_Application::render_details( $post )`: the answers table, the logo figures and the base matches, exactly what the Sponsors screen's open view prints minus its heading and its decisions. Folded, so the card stays a queue; the closed list stays on the Sponsors screen (S5's Recently decided).
8. **The Syncs card gains the sponsors sync as a fourth row**, from `WPCPM_Sponsors_Sync::progress()`, `last_read()` and `wp_next_scheduled( WPCPM_Sponsors_Sync::CRON_DAILY )`, linking to the Sponsors screen, behind `class_exists()`.
9. **The render order** on the Administrator Dashboard: strip, institution applications, Collaboration Agreements, semester reports, mentor requests, sponsor applications, sponsor posts, sponsor agreements, offers running low, new interests, the Sponsors card, programs running, syncs and health, then the resources. Spec 10 says "after the mentor requests card and before programs running", and the three shipped sponsor cards already sit there.
10. **No new options, no new post types, no new cron.** The phase reads what S1 to S5 wrote; uninstall parity needs nothing new, and `docs/sections/34-admin-operations.md`'s option table gains no row (its sponsor rows are complete since S5).

```markdown
## Offers, codes and claims

An offer is something your company gives the program's participants: a license, a plan, a credit, a course seat, a discount. It is of one of two kinds. **A pool of one-time codes** is a list of codes you paste or upload, one per line or as a CSV; each code is handed to one person, once. **One code or link everyone uses** is a single code or checkout link that every eligible person sees.

**Creating an offer.** The *New offer* form sits on the left of the *Offers and codes* card. Give the offer a title, say what a person gets in a sentence or two, how to redeem it, and where to find more information. Choose the kind. For a pool, paste the codes or upload a .txt or .csv file; codes are stored encrypted and shown only to the person who claims one. Choose who else the offer is open to: current students always are; mentors and the program team are your choice. Set the number of codes at which the program should warn you that the pool is running low and, if the offer has a last day, that day. Press *Create offer*: the offer starts as a draft that nobody but you can see.

**Your offers.** The offers you have sit on the right, under *Active offers*, each folded to its title, its state and a line of counts: for a pool, how many codes are available, claimed and void; for a shared code, how many people took it. Open one to edit it, to pause, resume or end it and, for a pool, to add codes or void the ones nobody has claimed. An offer that has ended, or whose last day has passed, moves under *Ended and expired offers*.

**States.** A **draft** is visible to nobody but you: switch it on when it is ready. A **live** offer is shown to the people it is open to; the one live offer marked *shown in the program records* is the offer the program's records name as yours. A **paused** offer is hidden until you resume it, and its codes stay. An **ended** offer is over: nothing more can be claimed, it cannot be resumed, and the codes already claimed stay with the people who hold them.

**Claims.** A participant claims an offer from their own page: a student from the Student Report Card, a mentor from the Mentor Report Card, both in a section called Tools from our sponsors. For a pool, the program hands out the next available code, seals it to that person, and never shows it to anyone else, including you. When a pool falls below the number you set, the *Offers and codes* card says so and the program mails you once.

**What you see.** The *Usage* card counts claims by month and by offer: a chart of the last twelve months, a table with the totals, and a CSV of the same. Nobody is named there: the program keeps the list of who claimed which code, so that it can help a person whose code failed, and does not share it.
```

## What your company can and cannot see

The Sponsor Dashboard shows your company its own things: its profile, its people, its agreement, its offers, its usage counts, its interests, its posts and its mentors. It never shows another sponsor's page, and it never shows who a student or a mentor is beyond what that person chose to make public.

- **Students.** You see counts: how many students each of your mentors guides, how many people claimed an offer. You do not see names, addresses, reports, grades or the notes of a call.

- **Records.** The details you save on your profile card, your logo, the offer marked *shown in the program records* and what you send from *What else would you like to support?* are written to the program's records, where program managers read them.

What you write on the dashboard is kept under the program's privacy policy, linked from the bottom of every page. Ask your program contact if you want something removed.

class WPCPM_Sponsor_Offers {
	const KIND_CODES  = 'codes';
	const KIND_SHARED = 'shared';
	public static function all() { return isset( $GLOBALS['offers'] ) ? array_values( $GLOBALS['offers'] ) : array(); }
	public static function live() { return array_values( array_filter( self::all(), static function ( $o ) { return 'live' === $o['state']; } ) ); }
	public static function is_live( array $offer, $today = '' ) {
		if ( 'live' !== $offer['state'] ) { return false; }
		if ( '' === (string) $offer['expires'] ) { return true; }
		return strcmp( (string) $offer['expires'], '' !== $today ? $today : gmdate( 'Y-m-d' ) ) >= 0;
	}
}
class WPCPM_Sponsor_Codes {
	public static function counts( $offer_id ) { return isset( $GLOBALS['codes'][ (int) $offer_id ] ) ? $GLOBALS['codes'][ (int) $offer_id ] : array( 'available' => 0, 'claimed' => 0, 'void' => 0 ); }
	public static function claims( $offer_id ) { return isset( $GLOBALS['claims'][ (int) $offer_id ] ) ? $GLOBALS['claims'][ (int) $offer_id ] : array(); }
}
class WPCPM_Sponsors_Index {
	public static function rows() { return isset( $GLOBALS['sponsor_rows'] ) ? $GLOBALS['sponsor_rows'] : array(); }
	public static function row( $record ) { $rows = self::rows(); return isset( $rows[ $record ] ) ? $rows[ $record ] : null; }
}

	const ARG_VIEW = 'wpcpm_sponsor_view';

	public static function page_url() { return 'https://site.example/sponsor-dashboard/'; }

class WPCPM_Institution_Audit {
	public static function sponsor_entries( $kind = '', $limit = 50 ) {

		if ( '' !== $kind ) { $rows = array_values( array_filter( $rows, static function ( $r ) use ( $kind ) { return $r['kind'] === $kind; } ) ); }

}
